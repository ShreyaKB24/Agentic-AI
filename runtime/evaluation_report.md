## 4. Key Takeaways & Architectural Differences

1. **Identity Grounding:** Assignment 1 accepts a student ID from the conversational prompt; Assignment 2 strictly binds identity to the cryptographically signed server-side session (`Flask session['student_id']`).
2. **Backend Authorization:** Data access control is enforced in Python code within tool dispatchers (`execute_tool`), NOT via LLM system prompts. Cross-student data tampering is completely neutralized.
3. **Sensitive Action Governance:** Course and record modifications are staged into an approval queue (`approvals.json`). Only authorized staff can transition a request to `approved` or `rejected`, preventing autonomous destructive operations.
4. **Auditability & Observability:** Every sensitive access attempt, login event, and approval decision writes an immutable structured audit log entry (`audit.jsonl`), with secrets automatically redacted.
